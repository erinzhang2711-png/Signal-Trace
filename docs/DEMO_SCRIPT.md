# 90–120 秒录屏脚本

目标：证明 SignalTrace 不是回答式聊天工具，而是一个“证据 → 规则 → 人工确认 → 版本”的金融事件工作台。全程不要给出买卖建议或涨跌预测。

## 0–12 秒：问题与产品定位

打开首页并说：

> 同一投资事件会被公告、新闻和传闻持续改写。SignalTrace 的目标不是预测股价，而是把当前结论、原始证据和结论为什么变化放在一起，并把不确定内容留给人工确认。

点击“海光信息 × 中科曙光”完整案例。

## 12–35 秒：同一事件与版本演化

指向左侧版本和中间时间线，说：

> 这是同一笔换股吸收合并的三个正式版本：筹划中、预案披露、持续推进。每一个版本都由时间线里的权威材料驱动，而不是由模型自行判断。

依次点击停牌公告、交易预案、最新进展公告；打开一次“公告原文”。

## 35–52 秒：证据与四个时间

保持最新进展公告被选中，指向右侧详情，说：

> 对每条证据，我保留发生、披露、抓取和更新时间。来源、原文短引和对当前结论的影响可以直接回溯；因此“交易已完成”这类说法不会因为出现得晚就自动覆盖公告。

## 52–68 秒：Agent、MCP 与停止边界

点击“立即监测历史快照”，展示 Agent 运行卡，说：

> 这是一个受约束的 Single Agent。它最多调用四个 iFinD MCP 工具来检索公告、新闻、披露事件和历史市场背景；模型只能提出草案，来源权重、调用上限和状态变化由规则层控制。

## 68–88 秒：传闻不会污染正式结论

在“导入新线索”点击“填入无来源传闻测试样例”，再点击“让 Agent 分析线索”。展示提议后说：

> 这里是一条称交易已经完成但没有公告链接的传闻。即使 Agent 能读懂文本，规则仍会把它放进人工核验，不创建新版本，也不改变当前结论。

如模型服务暂时不可用，改为展示表单和 README 的规则说明，并说明“异常不生成结论”。

## 88–110 秒：泛事件入口与人工确认

回到首页，输入一个非内置事件并运行，展示“候选材料收件箱”。说：

> 泛事件不会被硬画成正式时间线。系统先把 MCP 返回放进候选收件箱；研究员补充权威原文 URL 和正文后，Agent 才生成草案，最后由研究员点击确认建立正式事件。

## 110–120 秒：边界与收束

说：

> 当前 MVP 的完整、可复现案例是海光和中科曙光；全市场自动归并、实时调度以及更正/过期的完整交互是下一步。产品不提供任何投资建议。

## 录制前检查

- 使用 Vercel 生产 URL，浏览器缩放 100%，关闭含 Key 的页面和终端。
- 确认完整案例显示 v1、v2、v3；每条公告原文链接可打开。
- 若需要展示模型调用，先确认 Vercel 的模型环境变量可用；失败时录制明确的降级提示，不伪造结果。
- 视频时长控制在 100–115 秒，导出 MP4。
