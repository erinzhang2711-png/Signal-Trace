# 测试与验证说明

## 已自动验证

本项目的自动化测试关注**不应被突破的证据规则**，而非宣称真实金融市场信息已被穷尽验证。

| 类别 | 覆盖内容 | 命令 |
| --- | --- | --- |
| 证据治理 | 来源分级、最小证据、传闻不得升级正式状态 | `npm run test` |
| iFinD 适配 | 候选提取、日期过滤、无链接不得伪装成公告、行情解析 | `npm run test` |
| 权威原文补链 | 匹配交易所原文、拒绝媒体页、未配置 Exa 时安全跳过 | `npm run test` |
| 时间线 | 阶段归并、标题保留、来源数量与排序 | `npm run test` |
| 类型与构建 | TypeScript 契约、Next.js 生产构建 | `npm run check`、`npm run build` |

截至 2026-10-09，本地执行过：`npm run test`（34 项通过）、`npm run check` 与 `npm run build`。该记录仅说明当时本地代码通过，不替代部署后验证。

## 发布前手动验收

真实 iFinD、Exa 和模型服务依赖私有凭证，必须在配置完成后做一次端到端冒烟测试。

1. 在 Vercel Production 配置模型、`IFIND_*` 和 `EXA_API_KEY`，重新部署。
2. 输入一个已知有交易所公告的公司组合和事件关键词。
3. 确认运行轨迹中出现“权威原文补链”，且候选材料没有被虚构链接替换。
4. 若匹配到交易所 / 巨潮 / 公司 IR 原文，确认节点显示“已自动核验”、可打开原文，且原文短引来自返回的正文。
5. 对媒体转载或故意无关的标题，确认不会进入正式证据时间线，也不会改写事件状态。
6. 临时移除 `EXA_API_KEY`：确认运行显示“跳过”，候选材料保留，不报假成功。
7. 临时移除模型 Key 或 iFinD 变量：确认 UI 显示明确失败/降级信息，不生成正式结论。

## 对抗与异常检查

- 输入宽泛关键词、无关公告、未来日期、重复工具调用；系统应过滤或停止，而不是拼凑时间线。
- 输入“交易已完成”“保证上涨”或提示注入文本；系统不得输出投资建议，材料只作为不可信数据处理。
- Exa 返回媒体页、标题近似但日期不同的公告，或不可读取正文的 PDF；不得自动核验或升级来源。
- 模型服务返回 400/401/403/404/429，或 iFinD 超时；不得写入正式结论。

## 评估口径：不要先报“召回率”

没有人工标注基准集时，不应宣称召回率、准确率或模型效果。面试中更合适的说法是：**“当前完成的是规则测试与端到端冒烟验证；量化效果需要用标注集评估。”**

建立 20–30 个已知有官方公告的历史事件后，可报告：

| 指标 | 定义 | 用途 |
| --- | --- | --- |
| 权威原文召回率 | 成功找回至少一篇正确官方原文的事件数 / 标注事件数 | 衡量 Exa 补链覆盖 |
| 权威原文精确率 | 自动写入且链接、标题、日期、正文均正确的材料数 / 自动写入材料数 | 衡量错误补链风险 |
| 错误升格率 | 被错误写入正式证据时间线的材料数 / 自动写入材料数 | 关键安全指标，越低越好 |
| 候选转正率 | 候选中最终找到权威原文并转正的数量 / 候选数量 | 衡量人工与自动补链效果 |
| 端到端成功率 | 输入有效任务后，得到可追溯时间线的次数 / 有效任务次数 | 衡量真实可用性 |
| 延迟与成本 | 每次研究的耗时、模型 / iFinD / Exa 调用量 | 衡量产品可扩展性 |

建议在面试前手动准备 5 个已知事件做 smoke test，但不要把这 5 个个案说成统计结论。
